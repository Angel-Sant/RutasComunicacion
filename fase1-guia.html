0Antes de empezar: revisa el proyecto

El proyecto rutas-bilbao ya existe de una versión anterior. Antes de tocarlo, confirma que no tenga una base de datos en uso, porque las reglas nuevas cierran todo lo que no sea del transporte.

  1. Entra a console.firebase.google.com y abre rutas-bilbao.
  2. Menú izquierdo → Firestore Database.

Sobre el dominio rutas-bilbao.app

No es un correo real y no tiene que existir: Firebase solo lo usa como nombre de usuario. La auxiliar nunca lo ve, ella escribe ruta1 y la app completa el resto. Es la misma técnica que usamos en la app de Congregación.

Si en el panel le cambias la clave a una ruta (por ejemplo a ruta1bilbao), la cuenta de Firebase se debe llamar igual: ruta1bilbao@rutas-bilbao.app.

3Crear la base de datos

  1. Firestore Database → Crear base de datos.
  2. Edición: la estándar. Modo: producción.
  3. Ubicación: nam5 (Estados Unidos), igual que Comunica. No se puede cambiar después.

4Pegar las reglas de seguridad

Firestore Database → pestaña Reglas → borra todo lo que haya → pega el contenido del archivo firestore.rules → Publicar.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function coordinacion() {
      return request.auth != null
        && request.auth.token.email in ['miguel.santana.mon@bilbao.edu.mx'];
    }
    function auxiliar() {
      return request.auth != null
        && request.auth.token.email.matches('ruta[0-9]+@rutas-bilbao[.]app');
    }
    match /transporte/datos {
      allow read: if coordinacion() || auxiliar();
      allow write: if coordinacion();
    }
    match /bitacora/{id} {
      allow create: if auxiliar() || coordinacion();
      allow read: if coordinacion();
      allow update, delete: if false;
    }
    match /{documento=**} {
      allow read, write: if false;
    }
  }
}

Qué garantizan: solo tu correo edita la lista; las auxiliares la leen pero no la cambian; nadie sin contraseña ve nada. Para sumar otra persona de coordinación, se agrega su correo a la lista entre corchetes.

5Copiar la configuración a los dos archivos

  1. Engrane junto a "Descripción general" → Configuración del proyecto.
  2. Abajo, en Tus apps: si no hay ninguna web, toca el ícono </>, ponle de nombre transporte, sin marcar Hosting, y registra.
  3. Copia el bloque firebaseConfig que empieza con apiKey.
  4. Abre admin.html con el Bloc de notas o VS Code, busca var FIREBASE_CONFIG y reemplaza los valores vacíos por los tuyos.
  5. Haz exactamente lo mismo en index.html. Los dos archivos llevan la misma configuración.

Si prefieres, mándame aquí el bloque de configuración y te devuelvo los dos archivos ya llenos. Esas claves no son secretas: Firebase las diseña para ir dentro de la página, y lo que protege los datos son las reglas del paso 4.

6Subir a GitHub

Sube admin.html e index.html, reemplazando los anteriores. Ya puedes borrar del repositorio el datos.json: la app dejó de usarlo.

prueba.html sigue igual que antes: solo en tu computadora, nunca en GitHub.

7La primera subida de tus alumnos

Este paso es el más importante

La primera vez que entres al panel con la nube vacía, el panel sube lo que tenga guardado ese navegador. Tus alumnos de la Ruta 1 y la Ruta 6 viven en el navegador de la computadora donde los capturaste. Abre el panel en esa misma computadora y ese mismo navegador.

Por si acaso, antes de entrar descarga un respaldo: pestaña Importar/Publicar → DESCARGAR datos.json.

  1. Abre angel-sant.github.io/…/admin.html en esa computadora.
  2. Entra con tu correo y tu contraseña.
  3. Arriba a la derecha debe decir "Primera subida: 32 alumnos…" y luego "Guardado en la nube".
  4. Comprueba en Firebase → Firestore que aparezca la colección transporte con el documento datos.

Si en lugar de 32 dice "todavía sin alumnos", abriste otro navegador. No pasa nada: en Importar/Publicar usa Restaurar desde un respaldo con el datos.json que ya tienes, y se sube solo.

8La prueba de fuego

Necesitas el celular y la computadora al mismo tiempo.

  1. En el celular abre index.html, escribe ruta6 y su contraseña.
  2. Elige Mañana, COMENZAR RUTA, y marca a los niños de la primera parada.
  3. En la computadora, en el panel → Cambios del día → Hoy → busca a un niño de una parada que falte → No usa el transporte → motivo Enfermo → Registrar.
  4. En unos segundos, el celular debe vibrar y mostrar abajo: "Cambio de coordinación. Ya no va: …", y ese niño debe desaparecer de su parada.
  5. Termina y cierra la ruta. En Firebase debe aparecer la colección bitacora con el recorrido.

!Lo que todavía no hace

  • Los avisos a papás siguen sin llegarles. Se registran, pero eso es la fase 3, con OneSignal y Cloudflare.
  • Cada auxiliar puede leer la lista completa, no solo la de su ruta. Separarlo haría la lista mucho más difícil de mantener, y las seis son personal del colegio. Los papás, en la fase 2, sí verán únicamente lo de sus hijos.
  • El panel no se actualiza solo si dos personas lo usan a la vez: gana el último que guarda. Mientras seas solo tú, no importa.
  • La primera vez, la auxiliar necesita internet para entrar. Después la app funciona sin señal y sube lo pendiente al recuperarla.
